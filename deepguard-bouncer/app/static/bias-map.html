Accuracy by subgroup

Bias Map

One accuracy number can hide a subgroup the model does badly on — that's exactly how this project found that a 98% overall score was hiding a near-failure on one category of AI image. This page slices accuracy by generator, subject, and style so a hidden gap like that shows up on sight instead of by luck.

This is not one of the live checks on the main page. Grad-CAM, the frequency panel, and the region breakdown all answer “what does the model think of this photo, and why” — computed fresh on whatever you upload. This page answers a different question that a single upload can never answer on its own: “across many photos, where is the model systematically wrong?” Answering that requires already knowing the correct answer for every image in the set, to check whether the model's answer matches it. A live upload is exactly the situation where nobody knows the correct answer yet — that's the whole reason to ask the model in the first place. So this has to be a separate, deliberately pre-labeled set, scored all at once by hand-running a script, not something computed per upload.
