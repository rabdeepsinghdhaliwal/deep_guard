# Evaluation: the exam set, the calibration set, and before/after snapshots

Roadmap Step 0 ("the exam paper first"). Every later step — Content Credentials, watermarks,
a second detector, reverse search, the trust report — is judged against what is in this folder,
so that "it got better" is a measured statement, not a feeling.

> **Analogy.** A teacher who wants to know whether a class improved sets the *same* exam before
> and after the lessons, marks it with an answer key the students never saw, and keeps a separate
> practice paper for the students to learn from. Here the **exam set** is the exam, its labels are
> the answer key, and the **calibration set** is the practice paper: the only place anything is
> fitted.

## The three tools

| Tool | What it does | When to run it |
|---|---|---|
| `snapshot.py` | Records what the *running* app answers for a fixed set of inputs (API answers + page screenshots), and compares two recordings | Before and after every change to the app |
| `build_exam_set.py` | Builds the exam and calibration sets (downloads, pins, labels, checks); `--check` verifies every file against its SHA-256 | Once; again after adding your own pictures |
| `run_exam.py` | Scores the exam's detector images through `POST /api/analyze` (and the derived files directly with the same model objects) and writes the report card to `results/<label>/`; `--fit` fits the detector's temperature and the source panel's "unknown" threshold on the calibration set; `--write-bias-map` refreshes the Bias Map page | After any change to a model or to the verdict logic |

```
pip install -r evaluation/requirements-eval.txt     # once, into the app's venv
python evaluation/build_exam_set.py                 # ~3 GB download, ~20 min the first time
python evaluation/run_exam.py <label> --write-bias-map
python evaluation/snapshot.py capture <label>       # with the server running
python evaluation/snapshot.py compare <before> <after>
```

The images live **outside the repository**, in `$DEEPGUARD_DATA` (default `~/deepguard-data`,
about 0.9 GB): too big for git, and better kept out of a synced OneDrive folder. What *is*
committed are the two manifests, which record for every image where it came from, its label,
licence, size, format and SHA-256, and `commons_sources.json` (which Commons pictures, with credits).

How rebuildable each part is — `build_exam_set.py --check` flags any file that differs:

| Part | On a new machine |
|---|---|
| OpenFake, CNNDetection, GenImage (~1,000 images), C2PA test files | downloaded again from the same pinned dataset revision / git commit: byte-identical |
| The project's own images (52) | in this repository: identical |
| Commons pictures (15) | fetched again from Commons by title (list in `commons_sources.json`): all 15 checked byte-identical on 27 Sep 2026, though Commons could in principle re-encode its resized copies |
| Derived files (152: social-media copies, watermarked files) | regenerated by this script; identical only with the same library versions (Pillow, TrustMark, Video Seal, invisible-watermark) |

**Keep a backup of `~/deepguard-data`** (for example on Google Drive): it is the one copy of the
exact files every result in `results/` was measured on.

## The rules the exam set follows

1. **Labels are never guessed.** Every label comes from its source: a dataset that records
   real/AI and the generator, this project's own earlier test sets, or a Wikimedia Commons page
   that states it. The only machine-made column is `subject` (CLIP zero-shot, used only to group
   the Bias Map; the reports say so).
2. **Never fitted on.** The detector's temperature and the "unknown" threshold are fitted on the
   calibration set (OpenFake's *validation* split plus separate CNNDetection/GenImage samples) and
   only judged on the exam. The two sets share no image (checked by SHA-256).
3. **No leakage into Step 4.** The exam's OpenFake images come from its *test* split (generators no
   training split contains) and its Reddit set; Step 4 will train on OpenFake's *train* split, which
   shares no image with either.
4. **Derived copies are marked.** Social-media-style copies (`purpose=robustness`) and watermarked
   files (`purpose=layer1`) point at their original through `variant_of` and are never counted as
   independent images in the detector's scores.

## What is in it

`exam_set_manifest.csv` — one row per file. `purpose` says what the file is for:

| purpose | what it tests | from |
|---|---|---|
| `detector` | real vs AI, the page's verdict | OpenFake core/test (the 20 held-out generators in its two sampled shards, incl. GPT Image 1.5/2, Nano Banana Pro, Midjourney 7, Seedream 5, Sora 2, Veo 3; real ImageNet + DOCCI photos), OpenFake Reddit set (AI-art vs photography subreddits), CNNDetection (StyleGAN2, ProGAN, BigGAN, CycleGAN, StarGAN, GauGAN, whichfaceisreal + their real sets), GenImage (GLIDE, SD 1.4/1.5, ADM, VQDM, Wukong, Midjourney 5, BigGAN + ImageNet), our 44 outside images (DALL-E 3, Midjourney 5), the project's original 8 test images, 15 Wikimedia Commons pictures |
| `robustness` | does a messaging-app re-save change the verdict? | 80 exam images re-saved at long side ≤ 1600 px, JPEG quality 75 (a *simulation* — real WhatsApp round trips go in `incoming/`) |
| `layer0` | Content Credentials (Step 2) | the 26 C2PA public test images + 1 video, each with its documented expected result (valid / invalid and why / none) |
| `layer1` | watermarks (Step 3) | 12 exam pictures carrying Adobe TrustMark, Meta Video Seal or Stable Diffusion XL's reference mark, each also as a social-media copy; `expected` holds the embedded message |

`calibration_set_manifest.csv` — OpenFake core/validation (real LAION + Pexels photos and up to 3
images from each in-training generator) plus fresh samples of the source panel's own generators
(StyleGAN2, ProGAN, BigGAN, CycleGAN from CNNDetection; GLIDE, SD 1.4/1.5, BigGAN from GenImage).

Exact counts are printed at the top of every report (`results/<label>/report.md`).

### Adding pictures only you can supply

`build_exam_set.py` creates `$DEEPGUARD_DATA/exam_set/incoming/` with five folders, each holding a
note on what belongs there:

- `phone_real` — photos straight off your phones (by USB or Google Drive, **not** WhatsApp)
- `chatgpt_ai`, `gemini_ai` — images downloaded straight from the app (these carry Content
  Credentials, and ChatGPT/Gemini images also carry SynthID)
- `whatsapp_real`, `whatsapp_ai` — the same pictures after a WhatsApp round trip, saved back **under
  the same file name as the original**. That name is how a copy is paired with its original, so it
  is scored as a copy (did WhatsApp change the verdict?) and never counted as a second picture.

Then, offline: `python evaluation/build_exam_set.py --incoming-only` and
`python evaluation/run_exam.py <new label>`. The team's pictures are reported in their own section,
outside the headline, so the headline stays comparable with `BASELINE.md`.

## Honest limits of the exam itself

- **Resolution and format differ between real and AI groups.** OpenFake's ImageNet photos are
  ~500 px JPEGs; many AI images are 1024 px+ PNGs. The report breaks results down by size and
  format so a detector that learned "small JPEG = real" is visible, but the confound is real.
- **OpenFake's content is political/newsworthy** (its purpose); **Reddit labels come from the
  subreddit** (AI-art vs photography), so a few percent may be wrong.
- **The social-media copies are simulated**, not real WhatsApp output.
- **The C2PA test files are signed with test certificates**, so "valid" there means "the
  signature checks out", not "a trusted signer".
- **Only 6 of the source panel's 8 generators** have fresh samples (no DDPM or latent-diffusion
  set was found without an account); its "known tool" numbers cover those 6.
- **The 44 outside images are showcase pieces**, chosen by their makers to impress — harder than
  average, not a random sample.
